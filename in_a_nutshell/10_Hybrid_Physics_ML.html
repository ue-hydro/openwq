OpenWQ

Hybrid Physics–ML
Machine learning layered on the governing equations —
switchable, bounded, and exact-physics when turned off

The idea in one slide

OpenWQ keeps its physics & chemistry equations and adds ML on top, under explicit user control. Every ML component is opt-in and switchable; with all dials off the model is byte-identical to traditional OpenWQ.

Guiding principles

• Physics-first, ML opt-in
• Exact physics recovery (dials off)
• Bounded trainable dimension
• Inference in C++, training in Python

Three layers

• Layer 0 — per-cell parameters (foundation)
• Layer 1 — learn the parameters
• Layer 2 — learn a bounded flux correction

Layer 0 — Spatial parameters

Any parameter can be a per-cell field

The foundation both ML layers write into — and useful on its own (set per-HRU values from a soil/land-cover map, no ML needed). A parameter value is read three ways:

"beta_min": 0.0003                              // global scalar (default)
"beta_min": {"UNIFORM": 0.0003}                 // spatial, every cell = v
"beta_min": {"DEFAULT": 0.0003,                 // spatial, per-cell
             "CELLS": [[icmp, ix, iy, iz, v], ...]}
A plain number is the historical behaviour; the model is unchanged until a spatial field is supplied. Applies to BGC rate constants and the Freundlich/Langmuir isotherm parameters.

Layer 1 — Parameter regionalization

Learn the knobs, keep the equations

A small shared mapping sets each cell's parameter from static attributes: θ = g(attributes). The equations are untouched — only where on the parameter axis each cell sits is learned.

Why a mapping, not free values?

Calibrating one value per (cell × parameter) explodes and is ill-posed. A shared mapping has a fixed trainable size, independent of the number of cells — more cells become more constraint, not more unknowns.

Global-by-default

Regionalize only effective parameters (mineralization, denitrification tied to soil). Keep universal constants (stoichiometry, Arrhenius) global. Opt-in per parameter.

One shared mapping, per-cell parameters

Every cell can differ, yet the optimizer tunes only the handful of values inside the mapping (here, three per-class values) — a trainable size independent of the number of cells. Switched off, every cell falls back to one global scalar.

Config & calibration

"beta_min": {
    "VALUE": 0.0003,
    "ML_REGIONALIZE": {
        "rung": "per_class",            // or "regression"
        "attribute": "soil_class",
        "default": 0.0003,
        "attribute_table": "openwq_in/attributes.csv",
        "mapping_source":  "openwq_out/HDF5/...main.h5",
        "classes": {"sand":[1e-4,1e-2], "clay":[1e-4,1e-2], "peat":[1e-3,5e-2]}
    }
}
This one declaration is expanded into low-dimensional DDS sub-parameters (one per class or coefficient). Each evaluation the optimizer proposes those values, the mapping builds the per-cell field, and it is written into the config — calibrated end-to-end with the standard DDS machinery.

Mode A (offline) vs Mode B (runtime)

Mode A — offline bake

The mapping runs in Python; the resulting per-cell map is written into the config. No extra C++ — OpenWQ just loads the map (Layer 0).

Mode B — runtime NN

OpenWQ evaluates the trained network itself at start-up (a hand-rolled Armadillo MLP, no ML runtime) to fill the field, via ML_RUNTIME referencing weights + attributes files.

Ladder of flexibility, all DDS-friendly except the last: per-class → regression → (dPL neural network).

Layer 2 — Learned flux closures

A bounded correction to the flux

y = Φphysics(state, θ) · (1 + α · g(inputs))

Corrects the process itself — structural error no parameter can fix (a missing control, a wrong functional form). g is a small network bounded to [−1, 1].

α is the user's dial. At α = 0 the equation is recovered exactly. The total correction is clamped to ±max_correction — it can nudge a flux but never flip its sign or break mass conservation.

Wired into the BGC reactions, the sorption fluxes, and the erosion fluxes (HBVSED & MMF).
OpenWQ
12

Every stage of the correction is bounded

The learned term is squashed to [−1, 1] by tanh, scaled by the dial α, and clamped to ±max_correction before it multiplies the physics flux Φ. It can only reshape a flux within a fixed envelope; at α = 0 the multiplier is exactly 1.

Config & training

"ML_CLOSURE": {
    "ALPHA": 0.3,
    "MAX_CORRECTION": 0.5,
    "WEIGHTS_FILEPATH": "openwq_in/denit_closure.json"   // trained network
}

Because the closure sits inside the flux, its gradient runs through the physics. Training uses a differentiable emulator: the flux is re-implemented in differentiable form, the corrected system is unrolled in time, and the trajectory error is back-propagated (BPTT) into the network. Training is offline in Python; OpenWQ does inference only.

Train in stages: fit Layer 1, freeze it, then train Layer 2 on the residual — so the two ML layers don't trade off against each other.

Chained models & safety

Chained calibration

All three layers work in a chain (e.g. SUMMA-OpenWQ → mizuRoute-OpenWQ). Regionalized sub-parameters are tagged by model position and routed to the correct model — each with its own attribute table and reach mapping.

Backward-compatible

With every dial off the result is byte-identical to today's OpenWQ — verified in live runs. Trained networks are evaluated in C++ with no external ML dependency.

Decide whether to use ML, and how much. Layer 1 fixes wrong values; Layer 2 fixes a wrong process; the physics is always one dial away.
