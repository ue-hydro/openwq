Sensitivity Analysis

Morris Screening (Elementary Effects)

Efficient method to identify influential parameters with minimal model runs.

Cost: O(r × (k+1))

r = 10-20 trajectories, k = parameters

Example: 30 params × 15 trajectories = ~465 runs

Metrics

μ* (mu-star)Mean absolute effect → Overall influence
σ (sigma)Standard deviation → Non-linearity

Interpretation

μ* σ Meaning
High Low Linear influence → Calibrate
High High Non-linear → Calibrate carefully
Low Low Non-influential → Fix at default
Low High Interactive → Investigate
Typical result: Reduces 100+ params to 30-40 for detailed analysis

6

Sobol Sensitivity Analysis

Variance-based method for detailed sensitivity ranking.

Cost: O(N × (2k+2))

N = 1000-5000 samples, k = parameters

Example: 30 params × 2000 samples = ~124,000 runs

Indices

S1First-order: Direct parameter effect
STTotal-order: Including interactions

Interpretation

  • S1 ≈ ST: Parameter acts independently
  • ST >> S1: Strong interactions
  • Sum(S1) < 1: Significant interactions exist
Use after Morris: Apply Sobol only to the ~30 parameters identified as potentially influential

DDS Optimization

Dynamically Dimensioned Search (DDS)

Derivative-free optimization designed for expensive models.

Key Features

  • Reduces search dimensionality over time
  • Early: Explore many parameters
  • Late: Focus on few promising ones
  • No gradient computation needed
Typical budget: 200-500 evaluations for 10-15 parameters 
   DDS Behavior Over Iterations

   Early (exploration)
   ┌──────────────────────────────┐
   │ ████████████████████████████ │ Many params
   │ ██████████████████           │ perturbed
   │ ████████████                 │
   └──────────────────────────────┘

   Late (exploitation)
   ┌──────────────────────────────┐
   │ ███                          │ Few params
   │ ██                           │ refined
   │ █                            │
   └──────────────────────────────┘

   Probability of perturbation:
   P(i) = 1 - ln(i)/ln(max_iter)

Objective Functions

RMSE

√(Σ(obs-sim)²/n)

Root Mean Square Error

0 → ∞ (lower better)

NSE

1-Σ(o-s)²/Σ(o-ō)²

Nash-Sutcliffe Efficiency

-∞ → 1 (1 perfect)

KGE

1-√((r-1)²+(α-1)²+(β-1)²)

Kling-Gupta Efficiency

Recommended!

PBIAS

100×Σ(s-o)/Σ(o)

Percent Bias

-∞ → +∞ (0 perfect)
KGE advantages: Balances correlation (r), variability ratio (α), and bias ratio (β) — better for multi-species calibration

Temporal Resolution

Aggregate observations and model outputs to a common temporal scale before computing objective functions.

Available Resolutions

OptionUse Case
nativeOriginal timestamps (no aggregation)
dailyDaily patterns matter
weeklySmooth day-to-day noise
monthlySeasonal patterns, sparse obs
yearlyLong-term trends, budgets

Aggregation Methods

mean (default) | sum | median | min | max

Use mean for concentrations, sum for loads/fluxes

# Configuration in calibration file
temporal_resolution = "monthly"
aggregation_method = "mean"

# How it works:
# 1. Group obs by reach, species, month
# 2. Extract model outputs for same periods
# 3. Aggregate both to monthly means
# 4. Compute KGE/NSE/RMSE on aggregated data
Tip: Use monthly for sparse grab samples — ensures fair comparison with continuous model output
Output: Performance plots generated at specified resolution (time series, scatter, residuals)

Calibration Workflow

Step-by-Step Workflow

Copy the template → edit two paths → run → configure in the report → run the calibration.

Paths, modules, species, observations and container settings are all read from your model_config_template.py.

How to run a calibration

1

Copy the calibration template

Inside supporting_scripts/3_Calibration/ (needs calibration_lib/): cp calibration_config_template.py my_calibration.py

2

Edit the template copy

Set the two paths — model_config_path (your model_config_template.py) and calibration_work_dir. Optional: hpc_settings_json for HPC.

3

Run the template copy

python my_calibration.py auto-extracts the calibratable parameters and builds the “OpenWQ Calibration Setup Report”.

4

The Calibration Setup Report opens automatically

Set Targets, Parameters, the workflow-mode slider and the calibration/validation period; choose Docker or Apptainer in the Execution tab.

5

Execute the code snippets provided in the report

Run them sequentially.

6

Run the calibration & examine results

python my_calibration_run.py — Docker locally, or the auto-built SLURM job on HPC. The “OpenWQ Calibration Results Report” opens automatically.

Prerequisite — configure the model first

Your model_config_template.py must already generate correct inputs — its “OpenWQ — Configuration Report” confirms it. The calibration template then reads every model setting from there, so you only set two paths.

Two reports drive it

Setup reportTargets, parameters, mode, period & execution → saves the run script
Results reportMaps, convergence, per-species KGE / NSE / RMSE, Next Steps

Both are named after the calibration template.

Workflow mode (slider in the report): influential parameters · both · calibration — Morris/Sobol screening, DDS optimisation, or both.

Observation Data Sources

Two options for preparing observation data:

📄 Option 1: Manual CSV

observation_data_source = "csv"

  • Prepare data manually
  • Full control over format
  • Use any data source (USGS, EPA, local monitoring, etc.)

Best for: Custom datasets, local monitoring networks

🌍 Option 2: GRQA Database

observation_data_source = "grqa"

  • 43 water quality parameters
  • ~100 million observations worldwide
  • Auto station-to-reach matching
  • Local data or Zenodo download

Best for: Large-scale studies, data-rich regions

Local Data Support: GRQA supports pointing to local data folders if already downloaded from Zenodo

Running Calibration

Configure in the setup report, click “Save the script”, then run the generated <template>_run.py. The workflow mode (influential parameters · both · calibration) is set by the slider in the report and baked into the script — there is no mode flag. 

# Run locally with Docker:
cd .../containers && docker compose up -d  # start container
cd .../3_Calibration                       # where calibration_lib lives
python <template>_run.py            # run (mode set in the report)
python <template>_run.py --resume   # resume from last checkpoint
python <template>_run.py --clean    # delete stale eval_* first
python <template>_run.py --dry-run  # validate config, no run
python <template>_run.py --report   # (re)build the results report
Keep it awake: long runs are auto-prefixed with caffeinate (macOS) / systemd-inhibit (Linux) so the machine doesn't sleep mid-run. Progress is reported by simulated date through the calibration window.

Run modes (set in the report)

Influential paramsMorris / Sobol screening only
BothScreening → DDS calibration
CalibrationDDS optimisation only

CLI flags: --resume, --clean, --keep, --dry-run, --report.

On HPC (Apptainer)

Set Container runtime = apptainer in the Execution tab. The report builds a ready-to-run SLURM .sbatch and one-paste copy → re-point → submit commands (HPC details prefilled from hpc_settings.json) — nothing to edit.

Best Practices

✅ Do

  • Start with Morris screening to reduce parameters
  • Use log transform for rate constants
  • Split data: calibration + validation periods
  • Use KGE for multi-species calibration
  • Document parameter choices
  • Check physical plausibility of results

❌ Don't

  • Calibrate all 100+ parameters at once
  • Ignore parameter correlations
  • Use entire dataset for calibration
  • Accept physically unrealistic values
  • Skip sensitivity analysis
  • Overfit to noisy observations
Golden Rule: Fewer well-chosen parameters beats many poorly constrained ones

Post-Calibration Reporting

Interactive HTML Reports

Two self-contained, interactive HTML reports drive the workflow — a setup report (configure & launch) and a results report (diagnose the fit).

Setup report (configure & run)

  • Tabs: Overview · Settings · Targets · Parameters · Execution
  • Workflow-mode slider (influential params · both · calibration)
  • Calibration/validation slider with per-species observation coverage lanes
  • Live-updating Python script + “Save the script”
  • Flat step-by-step run locally / on HPC guide
  • HPC details prefilled from hpc_settings.json
Self-contained: single HTML file with embedded data — share via email, no server needed

Results report (diagnose)

Plotly chartsConvergence, parameter evolution, correlation, Morris/Sobol, obs-vs-sim + scatter
Observation mapStations coloured by performance
Per-figure exportLock-zoom + 📄 PDF (white, branded)
Per-species metricsKGE / NSE / RMSE / PBIAS
Next StepsApply best params · validate · refine
Dark/LightTheme toggle · sortable tables

Auto-Generated

Both are named after the calibration template (<template>_config_report.html / <template>_results_report.html); the results report opens automatically and can be re-built mid-run with --report.

Host-model observation semantics: for mizuRoute every matched station is primary (scored); for SUMMA only the pouring-point (HRU-outlet) station feeds the metric by default (use_primary_only=True) — untick “use only primary” to score the secondary stations too.
